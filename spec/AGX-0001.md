# AGX-0001: Signed single-object exchange envelope

Status: **experimental milestone snapshot**  
Version: **AGX/1**  
Wire compatibility: **not yet stable**

## Abstract

AGX/1 is a compact exchange envelope for moving one declared object across a controlled boundary. It binds payload bytes to a target boundary, direction, purpose, policy identifier, sequence, timestamp, display metadata, length, and SHA-256 digest. The manifest is deterministically encoded with CBOR and carried as the signed payload of a COSE_Sign1 structure using Ed25519.

This document describes what the milestone-1 implementation does. It is not a standards claim, certification, or promise of backward compatibility.

## Normative language

The terms MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are interpreted as requirements for this experimental implementation.

## Outer envelope

The outer object MUST be a definite-length CBOR map with integer keys in ascending order:

| Key | Type | Meaning |
| --- | --- | --- |
| `1` | text | Magic string, exactly `AGX1` |
| `2` | bytes | Serialized COSE_Sign1 containing the manifest |
| `3` | bytes | Exact payload bytes |

Unknown keys, indefinite-length items, duplicate keys, trailing bytes, and non-deterministic re-encodings are rejected.

## Signed manifest

The COSE protected header MUST contain:

- algorithm `EdDSA` (`-8`);
- an 8-byte key identifier equal to the first eight bytes of SHA-256 over the raw Ed25519 public key.

The unprotected header MUST be empty. The external additional authenticated data is the UTF-8 byte string `GlassBridge/AGX1/manifest`.

The COSE payload MUST be the deterministic CBOR manifest defined by [`agx1.cddl`](agx1.cddl). Milestone 1 requires exactly one object whose identifier is `1`.

## Receiver validation order

The receiver MUST:

1. enforce the maximum envelope size before parsing;
2. decode the fixed outer map and reject non-deterministic encoding;
3. require EdDSA and the expected key identifier in protected headers;
4. verify the COSE signature;
5. decode and deterministically re-encode the manifest;
6. enforce the expected boundary when supplied;
7. require exactly one object with identifier `1`;
8. compare the declared length to the actual payload length; and
9. compare the signed SHA-256 digest to the actual payload digest.

Only after every check succeeds may the payload enter the quarantine workflow.

## Resource limits

| Resource | Milestone-1 limit |
| --- | ---: |
| Payload | 64 MiB |
| Envelope overhead allowance | 64 KiB |
| Text field | 512 UTF-8 bytes |
| Object count | 1 |
| Frame source symbols | 1,024 |
| Frame symbol size | 64 KiB |

All maps and arrays MUST use definite lengths. Text fields MUST be non-empty and MUST NOT contain control characters.

## Direction and receipt semantics

Direction `1` means inbound and `2` means outbound. A sender signature proves authorization over the manifest; it does not prove reception or import.

After approved import, the receiver emits its own COSE-signed receipt using distinct external additional authenticated data: `GlassBridge/AGX1/import-receipt`. The receipt event `imported` means that the receiver observed successful verification and moved the payload to its generated import name. It does not assert execution, application acceptance, or any event on another host.

## Security and compatibility notes

- CRC on transport frames detects corruption; it does not authenticate frames.
- The payload is authenticated but not encrypted.
- Key provisioning and authorization policy are outside this milestone.
- Sequence is signed but persistent rollback enforcement is not yet implemented.
- Display names are untrusted metadata and never become receiver paths.
- Any incompatible wire change before stabilization may retain version `1` only on development branches. A public compatibility commitment requires a new protocol review and golden vectors.
